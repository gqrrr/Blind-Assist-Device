# 视障人士辅助避障穿戴设备--Blind-Assist-Device

> **项目简介**:
  本项目旨在开发一款基于多模态融合与深度学习的视障人士智能避障穿戴设备，帮助视障人士更安全、更独立地出行。
  主要结合USB摄像头(YOLOv8 视觉识别)、超声波测距与STM32主控板，通过触觉（扁平震动马达）和听觉（语音播报）为视障人士提供双重避障反馈。

## 技术栈
  * 视觉端:
  - 视觉识别--Python YOLOv8 OpenCV
  * 硬件端:
  - 测距--超声波测距
  - 主控板--STM32
  - 避障反馈--触觉（扁平震动马达）和听觉（语音播报）
  * 通信协议:
  - 串口通信（UART）

## 研发日志与已知问题
* **2026.11.20 有关摄像头循环退出问题**
   * 1. 问题描述：在test_yolo.py中，无法关闭视频画面窗口。
   * 2. 原因分析：在‘results = model(frame,verbose=False)’中，忘记写verbose=False，导致程序延迟较大。
   * 3. 解决方案：将‘results = model(frame)’改为‘results = model(frame,verbose=False)’。


* **2026.11.20 有关视觉识别误差记录**
   * 1. 问题描述：YOLOv8在识别某些目标时存在误差：① 图像中的纸箱和A4纸被识别为laptop；② 图像中的水杯被识别为banana/remote/person。
   * 2. 原因分析：官方模型用于训练的数据集所包含的类别较少（仅有80个），无法准确识别图像中的纸箱、A4纸、水杯等目标，导致模型产生误判。
   * 3. 解决方案：后续计划通过收集特定场景图片，对模型进行微调，以提高识别准确率。

* **2026.11.21 有关阈值参数调优与硬件配置记录**
  * 1. 问题描述：在实际测试中，发现原本设定的判定危险的阈值过低，在距离较远的情况下，就判定为危险情况，导致误报，容易造成恐慌。
  * 2. 原因分析：不同摄像头的视场角会影响距离和面积的线性关系，导致物体在画面中的放大率存在差异；且人体体积较大，容易较早达到面积阈值。单一的面积阈值不足以精确代表实际距离。
  * 3. 解决方案：通过多次测试和调整，将面积占比从一开始的 15% 上调至 25%，后续也会使用超声测距，使其更符合实际应用场景，避免误报和漏报。同时代码成功适配外接USB摄像头（将VideoCapture索引改为1），可用于后续穿戴使用。

* **2026.11.23 有关马达连接和驱动记录**
  * 1. 问题描述：在通过MOS管连接马达后，发现mos管上面的灯可以正常根据超声波测距结果闪烁，但是马达不能正常产生震动。
  * 2. 原因分析：1.可能是连线出错。2.代码问题。3.电压不够。4.马达损坏。5.mos管损坏。
  * 3. 解决方案：排查连线问题，用测试代码重新测试，发现mos管上的输入指示灯常亮但马达依旧不转，用两节1.5v电池测试马达，发现马达可以正常产生振动，排除了马达损坏的可能性。用LED接mos管的OUT+/-，发现LED发光不稳定。最后询问客服，说mos管不合适。马达问题推迟解决

* **2026.11.23 有关语音播报连接和驱动记录**
  * 1. 问题描述：接入语音模块的时候，播放出来乱码，无法正常播放。
  * 2. 原因分析：编码没有完全从UTF-8转到GB2312，导致播放出来是乱码。
  * 3. 解决方案：将main.c文件重新另存，编码改为ANSI，重新烧录，可正常播放。

* **2026.11.23 有关语音播报信息记录**
  * 1. 问题描述：语音播报过程中存在漏读现象。
  * 2. 原因分析：1.可能是逗号卡顿。2.可能是串口发送过快。3.可能是字符数组溢出。4.延迟时间过短，话没说完就重新播报了
  * 3. 解决方案：逐一排查，将逗号改为其他字符，多说了一个字，不能解决实际问题；串口发送用for循环增加延迟，不能解决；将frame【100】改为frame【300】，没有解决；增加延迟时间，确保话音播报完毕再发送下一条指令，解决漏读问题。
